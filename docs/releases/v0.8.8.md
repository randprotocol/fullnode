# v0.8.8 — chain 22: open validator mint

**Fork height: chain 22 block 140 000** (expected around 2026-11-23 00:08Z). Every host must run
v0.8.8 before then. The owner signs `SHA256SUMS` on a real TTY.

v0.8.8 is a **height-activated consensus change on the live chain 22**. It is not a chain cut:
chain 22's genesis file and its hash (`29d67542941f2eb6f2c1bb68c759926f5d814c9e2c7a934292806a2d98b7e9c0`)
do not change, and the release is rolled onto the running fleet.

## The rule (owner's decision, 2026-11-22)

Any address can mint RAND for itself if it runs a validator node. From the activation height `H`
on, the ledger's `Action::Mint` validation stops enforcing both genesis lists:

- `staking.faucet_recipients` (`TxError::FaucetRecipientNotAllowed`): a mint may pay any recipient;
- `staking.faucet_minters` (`TxError::MinterNotAllowed`): any key with a row in the validator
  register may sign it.

These rules are unchanged:

- `faucet: true`;
- `FAUCET_MAX_UNITS` (100 RAND) per mint;
- `faucet_budget_per_epoch` (10 000 RAND per 1 000-block epoch), shared by every minter;
- the register row (`TxError::MinterNotValidator`);
- the minter's signature;
- the `mint_commitment` value rule;
- `admission_by_vote`, which decides who gets a register row at all.

Below `H` the old rules hold exactly, so a replay of blocks below `H` gives the same result.

The node follows the same height:

- **Pool policy.** `admission::minter_not_allowed` allows only the genesis-list minters, and steps
  aside once the pool's ledger is at `H`.
- **`rand_mint` and `rand_status.faucet`.** Both use `admission::faucet_refusal_at`. From `H` on, a
  registered validator serves `rand_mint`, and `faucet` flips to `true` at the first commit past
  `H`.
- **Refusal cache.** `FaucetRecipientNotAllowed` is no longer cached as a permanent refusal,
  because it now depends on the height.

## Where `H` lives

- `crates/randprotocol-core/src/ledger/staking.rs` holds `CHAIN_22_OPEN_MINT_HEIGHT` and the
  `OPEN_MINT_ACTIVATIONS` table, keyed by genesis hash.
- `Genesis::build` sets it on the ledger.
- `node::reload_ledger_from` restores it on every restart.

## Roll (flag day)

Every validator, observer and archive must run v0.8.8 before the chain reaches `H`. A node still
on v0.8.7 at `H` refuses the first unlisted mint its peers apply and forks off. Before `H`, v0.8.8
and v0.8.7 agree on every block, so the roll can go one host at a time with no halt.

## Rollback

Before `H`: reinstall v0.8.7, on the same datadir. After an open mint has been applied: no
rollback on the same datadir. Moving back would need a new build that drops the rule from a later
height.

## Open questions

- Chain 22 has a bridge. If faucet RAND can leave through it, the faucet now
  sits beside the bridge without a recipient list, which is the case `GenesisError::FaucetWithBridge`
  was written against. The owner accepted this on the grounds that `admission_by_vote` gates who
  becomes a validator. The genesis-time check is unchanged.
