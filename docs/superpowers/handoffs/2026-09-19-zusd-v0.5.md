## 1. The goal (user, 2026-09-19)

zUSD can be minted, transferred and burned on RandProtocol, backed by USDT and USDC bridged from
Tron, Solana, BNB Chain and Ethereum, and can be bridged back. **Security invariant: the USDT + USDC
in custody on the four chains is always at least the zUSD supply on Rand, and it is checked before
every unbridge.** Once transfers, mint and burn work, run a live round trip on the already-deployed
mainnet endpoints with the `RAND_BRIDGE_TESTER` accounts from the user's `~/.zshrc` (bridge in → zUSD
→ bridge back), on each chain. **When the goal is met: tag `v0.5` on GitHub (`randprotocol/fullnode`)
and publish a release with a beautiful message in the v0.3/v0.4 emoji format.**

## 2. Decisions the user made (do not re-litigate)

1. **RPL** is RandProtocol's own token standard (the user chose the name). A token is a *shielded
   native asset*: an entry in one ledger registry, balances held as notes — not a contract (programs
   are stateless; a `Call` writes only a receipt).
2. **Creating a token is permissionless**; units are issued only under the mint authority fixed at
   registration (`None` / `Key` / `Bridge`; `Program` reserved). **Symbols are not unique**, like
   ERC-20 and SPL; identity is the asset id.
3. **Fees are paid in RAND**; a sender must hold RAND (like ETH for an ERC-20).
4. **Allowances** (approve / transferFrom) are allowance accounts on a shared sub-key (option A), no
   consensus change; program-owned notes are RPL-2. **No freeze, blacklist or pause** on Rand.
5. **One zUSD** instead of zUSDT + zUSDC, until Tether/Circle issue natively: backed jointly by
   **seven backings** — USDT and USDC on Ethereum (chain 2), BNB Chain (3), Solana (5), and USDT only
   on Tron (4) (Circle discontinued Tron USDC). The user **accepted the pooled-backing risks**
   (depeg contagion, an at-par conversion venue) with no Rand-side per-backing share cap.
6. **The transaction-binding security fix is approved** ("yes to fix the security hole").
7. **Hide the asset on a spend before launch** ("do option 2, build the hidden-asset guest first"):
   chain 14 must not reveal which token a transfer moves.
8. The whitepaper and `../references/src/06-zusdt.md` are already rewritten for one zUSD with seven
   backings (whitepaper pushed `79bcb97`, `e93fdd5`).

## 3. The invariant as built

- Each backing is `(chain, token, decimals, locked)`. A deposit (`BridgeAttest`) does `locked +=
  amount` and `total_supply += amount`; a `BridgeBurn` does both `-=`. `lock`/`release` are the only
  writers, so **`total_supply == Σ locked` by construction** (debug-asserted at block close, and the
  token leaf commits every `locked` into the state root).
- The deployed endpoints are fee-free on lock and deduct the full attested amount on release (the
  10 bps and the relayer fee come out of it), so **each backing's `locked` equals that endpoint's
  `custody(token)` exactly**, modulo in-flight messages.
- **Before every unbridge**, Rand refuses a `BridgeBurn` unless: the named `(to_chain, token)` is a
  backing of zUSD (`NotABacking`); `amount <= locked` of that backing (`InsufficientBacking`); the
  amount and the relayer fee are whole release units, `10^(8-d)` for a `d`-decimal source coin
  (`NotReleasable`, so custody equals locked to the last unit); for chains 2–4 the upper 12 bytes of
  `to` are zero. The endpoint independently refuses a release above its custody. The bridge
  session's `rand-bridge-audit` (bridge `d1f3418`) reconciles `locked` per backing against each
  endpoint's custody.

In flight at the time of writing:
- **Task 5b — transaction binding** (security, pre-existing on main). A transaction is `{chain_id,
  bundle, action}` with no signature, and a bundle proof binds only `anchor, nullifiers,
  commitments, fee, burn, asset, time` — so anyone could copy a `BridgeBurn`, swap `to`, and steal the
  release; or swap a `Bond`'s validator; or replace envelopes. Fix: every bundle is proved with, and
  verified against, public words `H("rand-tx-bind-1", chain_id ‖ tx with proofs blanked)` through the
  constraint-set-6 public input segment (no circuit change; `executor.rs` is local code). Brief:
  `task-5b-brief.md` in the ledger directory (includes the bridge session's review additions: a table
  of bundle-less signed actions, canonical encoding, a no-wildcard blanking match).
- **Hidden-asset spike** — measuring a 4-slot guest (two private-asset slots + two RAND slots, one
  proof per transfer) against today's `bundle()` (3811 words, tier 14, ~95–100 s). Report lands at
  `spike-hidden-asset-report.md` in the ledger directory.
