## Global Constraints

- Chain 14 unchanged: same genesis hash, same state roots, same consensus rules; only storage layout (§2) and node behaviour change. Rollback below v0.5.5 needs a resync (the QC rows are gone) — the release notes say so.
- Every rule change ships with a test watched failing first; quote the red in the commit.
- No new column family.

## Review Focus

1. A database whose `CF_QCS` still holds every row (written by v0.5.4) must be pruned exactly once and answer `committed_block(h)` identically before and after — Task 1's migration test.
2. `truncate_to` on a pruned database must leave the new head with a QC row, or the next `head_qc()` is `Corrupt` — Task 1's truncate test.
3. A pending set whose first block does not extend the head (crash between commit and the empty `PersistPending`) must be dropped silently, never inserted — Task 2's stale-pending test.
4. The balance page with a pasted spend key must refuse and clear the field, never derive `nk` from it — Task 3's test.
5. WEB-5: a transfer reported by source 1 with a different amount than source 2 must not be credited — Task 4's mismatch test.
