# Delegated Proving, Phase 2 (v0.6.3, chain 17) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Split authorisation: the spend key leaves the bundle guest for a tiny auth proof the wallet makes itself, so a prover holding only the viewing key can prove a bundle but never spend. Ships as v0.6.3 and the chain-17 genesis (a hard fork: new `Bundle` fields, new guest, new digest).

**Architecture:** Guest v3 (`bundle_hidden_v3`, fullnode-local, hand-assembled like v1/v2) takes `nk` and a fresh `salt` instead of `sk`, derives `pk_self = H(PK, nk)`, computes `c = H(AUTH, nk, salt)` and folds `c` into its digest. A new auth guest takes `sk` and `salt`, derives `nk`, publishes `c`, proved against the same transaction binding. `Bundle` gains `auth_commit` and `auth_proof`; the ledger recomputes the digest with `auth_commit`, verifies the auth proof against the binding and requires its output to equal `auth_commit`. Genesis pins `hc_bundle` = v3 and a new `hc_auth`. The prover service accepts `ViewingKey` jobs for v3 and can charge a fee paid as one RAND output inside the bundle. Chain 17 is cut from chain 16's snapshot the way chain 16 was cut from chain 15.

**Tech Stack:** as Phase 1, plus the zkVM assembler (`crates/randprotocol-zkvm/src/asm.rs`, `guests.rs`) — node-local files excluded from `deploy/sync-zkvm.sh`, so no circuits change.

**Spec:** `docs/superpowers/specs/2026-09-28-delegated-proving-design.md` §4 (construction, costs, rejected options, soundness review), §5 (fees), §6. Phase 1 plan: `docs/superpowers/plans/2026-09-28-delegated-proving-phase1.md`.

**Branch / base:** `feat/delegated-proving-2` off the `v0.6.2` tag. **Preconditions:** v0.6.1 tagged (the cs7 freeze on `crates/randprotocol-zkvm` is over), v0.6.2 tagged, chain 16 live.

## Global Constraints

- Auth guest: private `sk, salt`; `nk = H(NK, sk)`; `c = H(AUTH, nk, salt)`; publishes `c` (8 output words); proved against the transaction's binding as the public segment (spec §4.1).
- Bundle guest v3: private `nk, salt, the rest as today`; `pk_self = H(PK, nk)`; `c = H(AUTH, nk, salt)`; `digest = H(…today's fields…, c, bad)` (spec §4.1).
- `Bundle` gains `auth_commit: Word8` (the public `c`) and `auth_proof: Vec<u8>`; `Transaction::binding` blanks both proofs (spec §4.1).
- The ledger verifies the auth proof against the binding it recomputes and requires its output to equal `auth_commit`; the bundle digest it recomputes includes `auth_commit` (spec §4.1).
- `salt` is 256 fresh random bits per transaction; the wallet enforces freshness and a test asserts it (spec §4.1).
- Addresses, keys and existing notes do not change: `pk = H(PK, nk)` stays (spec §4.1).
- One shape for every transaction: a self-proving wallet makes both proofs; self-proved and delegated transactions are indistinguishable (spec §4.1).
- Genesis selects it like `hc_bundle` selects v1/v2 today: `--bundle-guest v3` and a new `hc_auth` pinning the auth guest (spec §4.1). `hc_auth` is hashed into the genesis only when present, so chains 14–16 hash unchanged.
- The measurement gate (spec §4.2): Phase 2 ships only when aggregation is active on the target chain, or the auth proof keeps two transfers per block, or the owners accept the throughput. **The owner accepted the throughput on 2026-09-28** ("execute phase 2 … and cut the chain"); Task 1 still measures and records the numbers.
- Soundness review before shipping (spec §4.4): the six cheating cases with real proofs.
- Fee (spec §5): `prover_info.fee` quotes a flat RAND amount and the prover's shielded address; the wallet adds one RAND output paying it (slot table in §5); the prover checks the witness's outputs name its `pk` with at least the quoted amount and refuses otherwise; no subsidy, no public field.
- The new hash domain tag is node-local like `HIDDEN_BUNDLE_DOMAIN = 64`: `AUTH_DOMAIN = 65`, asserted outside `1..=0x3f` and `≠ 0xff` and distinct from every tag the crate has (`tests/hidden_bundle.rs`'s existing assertion, extended).
- Every real-proof test takes the workspace `proving_slot`. No `cargo fmt`. Node-local zkVM files only: `guests.rs`, `asm.rs`, `hidden.rs`, `executor.rs`, `tests/hidden_*.rs`, `tests/guest_provenance.rs` and the new `src/auth.rs` / `tests/auth*.rs` (add them to `deploy/sync-zkvm.sh`'s two exclude lists in the same commit that creates them). Never touch a vendored file.

## Review Focus

1. **An auth proof replayed from another transaction** (same `c`, different binding): the ledger must refuse — Task 5 (`an_auth_proof_for_another_binding_is_refused`), Task 3 real proof.
2. **A bundle whose `auth_commit` is not the `c` its digest was computed with**: the digest check catches a mismatch between the field and the guest's `c` only because `c` is in the digest — Task 3 (`auth_commit_outside_the_digest_is_refused`).
3. **A repeated salt across two transactions** links them: the wallet must never reuse one — Task 7 (`two_sends_never_share_a_salt`).
4. **A v3 chain receiving a v2-shaped transaction** (empty `auth_proof`, zero `auth_commit`): refused at admission as a wire/validity error, never a panic in the decoder — Task 5.
5. **A fee output in the wrong slot or asset** (a token transfer paying the prover fee from the asset slots): the prover must refuse, not accept a worthless token as payment — Task 8 (`a_fee_paid_in_the_wrong_asset_is_refused`).
