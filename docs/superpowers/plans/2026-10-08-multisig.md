# Multisig Accounts Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** M-of-N controlled public per-asset balances (a multisig register) seeded at genesis for the treasury and creatable later, with four genesis-gated actions: `CreateMultisig` (40), `MultisigDeposit` (41), `MultisigPay` (42), `MultisigRotate` (43) — after the perps actions (34–39), which merged first.

**Architecture:** A new core module `ledger/multisig.rs` owns the config, the derived account id, the register (accounts with signers, threshold, nonce and a per-asset vault), its root, the signature rules and the four actions' validate/apply. `Genesis` gains an optional `multisig` section seeded into `Ledger::multisig: Option<MultisigRegister>`; `Ledger::state_root` wraps the root under `rand-state-multisig-1` only when present. The node persists the register as bincode under `META_MULTISIG`, claims one pooled Pay-or-Rotate per account (mempool role 9), and serves `rand_getMultisig`, the `multisig_*` supply rows and the limits. `rand-node` carries `genesis --multisig` (prints the derived ids) and the `multisig id|status|pay|rotate` tree (the vesting revoke's prepare/sign/submit); the wallet carries `rand multisig create|deposit`.

**Tech Stack:** Rust workspace (randprotocol-core, randprotocol-node, randprotocol-client), bincode + serde_json, Dilithium2 (`crypto::PublicKey`), BLAKE3 `merkle_root`, clap.

**Spec:** `docs/superpowers/specs/2026-10-08-multisig-design.md` (read it first; user guide to be written as `docs/multisig.md`).

## Global Constraints

- A genesis without `multisig` builds, hashes and roots byte for byte as today: `chain_20s_genesis_file_builds_chain_20` (node `main.rs:3423`), `the_genesis_hash_is_pinned` (`main.rs:3911`) and `the_consensus_encoding_and_txid_are_pinned` (`transaction.rs:1190`) stay green untouched.
- `Supply` is a positional bincode blob: **never add a field to it**. The counters live in `MultisigRegister` and reach the audit through `Audit::with_multisig`.
- The four variants are **appended after `Invoke`** in `enum Action` (tags 34–37; a tag is the bincode position). `VARIANTS` becomes 38.
- Domains: id `rand-multisig-id-1`; messages `rand-multisig-pay-1`, `rand-multisig-rotate-1`; leaf `rand-multisig-leaf-1`; root `rand-multisig-root-1`; state wrapper `rand-state-multisig-1`; genesis commit tag `multisig`.
- Bounds: `MAX_SIGNERS = 10`, `MAX_CREATE_FEE = 1_000 * UNITS_PER_RAND`, payouts `1..=program_state::MAX_PAYOUTS` (4).
- A Pay debits `gas::BUNDLE_BASE` from the account's RAND row to the proposer's `rewards`; a Rotate is fee-less. Both carry no bundle (`Action::bundle_less`). Create and Deposit ride a bundle whose `burn_r` / `burn_a` fund the vault.
- Payout notes are `program_state::payout_commitment(p, time, executor)` (the `PROGRAM_FROM` sender word), appended with `Ledger::deposit` and rebuilt from the transaction everywhere an `Invoke`'s are.
- `Audit::with_multisig` is chained **last** in `Ledger::audit()` and in `rand_getSupply`: `with_vesting` recomputes `pool_value` from `supply`, so anything before it is lost.
- Every rule is a red test first; quote the red in the commit. Never `cargo fmt` the repo. After touching `Genesis` or `Action`, run `cargo check --workspace --tests` (a `--lib` gate misses `main.rs` and `tests/`).
- Commit messages end with the two attribution lines this session uses (`Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>` and the `Claude-Session:` line).

## Review Focus

1. A Pay pooled against the head whose account another pooled Pay drains must leave the pool at selection, not fail at apply — `still_applies` test in Task 5 (mempool) and Task 4 (core).
2. A Rotate and a Pay at the same nonce: whichever lands first kills the other; a Pay signed by the *old* signers after a Rotate is `BadSignature`, not accepted — Task 4.
3. One bad signature among `threshold` good ones refuses the action (never "a smaller quorum") — Task 4.
4. A restarted node restores the register (nonces, vault rows, rotated signers) and recomputes the wrapped root; a database without the blob on a genesis with the section is refused — Task 5.
5. An account holding only tokens cannot pay (`VaultShort { asset: 0 }` on the base), and the recipient's wallet finds a payout note from the transaction alone — Task 4 and Task 7.

```rust
pub fn account_id(chain_id: u64, salt: &[u8; 32], threshold: u8, signers: &[PublicKey]) -> [u8; 32] {
    let mut b = Vec::with_capacity(42 + signers.len() * PUBLIC_KEY_LEN);
    b.extend_from_slice(&chain_id.to_be_bytes());
    b.extend_from_slice(salt);
    b.push(threshold);
    b.push(signers.len() as u8);
    for k in signers { b.extend_from_slice(k.as_bytes()); }
    Hash::digest_domain(b"rand-multisig-id-1", &b).0
}

pub fn check_signers(signers: &[PublicKey], threshold: u8) -> Result<(), String> {
    if signers.is_empty() || signers.len() > MAX_SIGNERS {
        return Err(format!("{} signers, an account has 1..=10 signers", signers.len()));
    }
    for (i, k) in signers.iter().enumerate() {
        if k.as_bytes().len() != PUBLIC_KEY_LEN { return Err(format!("signer {i} is not a Dilithium2 public key")); }
        if signers[..i].contains(k) { return Err(format!("signer {i} is listed twice")); }
    }
    if threshold == 0 || threshold as usize > signers.len() {
        return Err(format!("threshold {threshold} is outside 1..={}", signers.len()));
    }
    Ok(())
}
```

```rust
fn check_signer_set(a: &Account, signatures: &[SignerSignature]) -> Result<(), MultisigError> {
    // MAX_SIGNERS is 10, so an index that passed the bound fits a u16 mask; a list longer than
    // the signers necessarily trips the bound or the mask.
    let mut seen = 0u16;
```
